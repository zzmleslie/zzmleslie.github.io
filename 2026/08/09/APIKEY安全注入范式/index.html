API Key 安全注入范式：从「写死代码」到「零信任部署」

基于 GitHub Actions → 云服务器 的实战经验，提炼一套通用、可复现的 API Key 全生命周期管理方案。

一、核心原则：三条不可妥协的底线

原则 含义 反面教材
不进仓库 任何密钥不得出现在 Git 历史、配置文件或构建产物中 把 api.key=sk-xxx 提交到 application.properties
不进构建产物 密钥不应被打包进 jar/docker image，避免镜像泄露即密钥泄露 在 Dockerfile 里 ENV API_KEY=xxx
只在运行时注入 密钥仅在进程启动时通过环境变量/挂载文件进入内存 把密钥写在 systemd 的 ExecStart 命令行参数里
