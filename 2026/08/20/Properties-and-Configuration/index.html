part1: maven资源展开（限制条件：生产环境即源码 main 中，test 中不行）

资源过滤

  1. 在 application.yml / properties 中，常用 @ @ 占位符来避免硬编码，是从已解析的 pom.xml 中找到占位键对应的值，进行替换后写入 target / classes 中的 application.yml。例如在 src 中 application.properties 中写 version = @project.version@ 替换。

  2. 展开属性，也就是占位符的替换，是由 maven 在编译、打包期间进行的。maven-resources-plugin 是执行者，这个插件是 pom.xml <parent> 中配置 spring-boot-starter 就自带的。常在 pom.xml 中 <parent>自带的。

    Tips:如果不用 starter-parent 需要在prom.xml中添加和相关内容

  3. 展开属性失效：当开启 addResources 标识的时候，开启 addResources 的同时，也开启了热重载（hot reloading），将 src/main/resources 挂载到运行的 classpath 上

TIP：这里的挂载是什么？有什么效果？
正常（非挂载状态下），Java 程序运行只能读取 target / classes（即编译后的目录）中的文件，如果在程序运行时修改源码，程序并不能直接展现变化，必须再次经过一次 maven 编译和拷贝更新。
而挂载则是将源码路径 src/main/resources 追加到 classpath 上，使得源码修改可以立刻生效，而无需编译，便于开发。

part6：设置激活的 Spring Profile

什么是 profile，我们为什么要激活它?

profile 是 spring 框架提供的一种环境隔离机制，它允许开发者把针对不同运行环境的配置和组件分隔开，当某一 profile 被激活，对应的配置和组件才会生效。

在开发过程中，我们需要在不同环境中运行一套代码，通常会有：dev 开发环境 prod 生产环境 。这些环境的数据库连接、日志级别、API 注入方式等都会存在很大差异，而每次手动修改配置则很容易出错也很吃力。于是我们引入了profile，便于快速切换环境。
